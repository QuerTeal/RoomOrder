# 키오스크 설치 안내 — 2.4.1

8개 방 모두 같은 `dogdive-order.apk`를 사용합니다. 2.1·2.2·2.3 통합 앱 위에 설치하면 PIN·방·화면·키오스크 설정을 유지합니다. 처음 설치할 때 기본값은 **자동 실행 미지정, 앱 잠금 꺼짐, 화면 켜짐 유지 켜짐**입니다.

2.6.1에서는 자동 정리 후 쉬는 동안 10분마다 같은 방의 원본 QR로 다시 접속해, 오래 비어 있던 태블릿의 첫 메뉴 터치에서 `QR을 다시 인식해주세요` 화면이 나오지 않게 합니다. 화면이 꺼져 있어 재접속하지 못했다면 첫 터치로 먼저 다시 접속합니다. 미조작 시 자동 정리를 켠 태블릿에만 적용되며, 별도 설정은 없습니다.

2.4.0의 다크모드는 **관리자 설정 → PIN 인증 → 다크모드 → 저장**에서 켭니다. 태블릿별로 저장되며 재실행·부팅 후에도 유지됩니다. 끄고 저장하면 밝은 화면으로 돌아갑니다. 기본값은 꺼짐이며 메뉴·장바구니·확인창과 앱 안내 화면에 적용합니다. 테마만 변경할 때 현재 페이지를 새로고침하지 않습니다.

2.3.4에서는 장시간 미조작 후 `QR을 다시 인식해주세요` 화면이 나오면 약 4~6초 후 같은 방의 원본 QR 링크로 자동 접속합니다. 메뉴 로딩 시간은 별도이며 정상 메뉴·장바구니·결제 입력은 유지합니다. 요청 진행 중에는 기다리고, 주문 결과가 불확실하면 자동으로 복귀하지 않습니다. 이 기능은 별도 설정 없이 적용됩니다.

2.3.3에서는 수량 조절·장바구니 메뉴 삭제 중에도 현재 화면을 유지합니다. 초기 로딩·페이지 이동·담기·주문 처리에는 대기 안내를 표시합니다. 변경 요청 처리 중 반복 터치와 뒤로 가기 차단은 유지합니다. 시간 초과 등으로 결과가 불확실하면 `장바구니 확인` 또는 `주문내역 확인`을 눌러 결과부터 확인하세요. 관리자 PIN 화면에는 계속 진입할 수 있습니다.

2.3.0에서는 토스의 세션 종료 안내가 일정 시간 유지되면 같은 방의 첫 주문 화면으로 돌아갑니다. 주문 완료나 결제 진행 중인 화면은 유지합니다. 네트워크 또는 토스 운영 상태 때문에 재접속이 반복 실패하면 “메뉴 처음으로” 버튼을 사용하세요.

2.3.1에서는 WebView 주문 화면이 비정상 종료되면 네이티브 복구 화면을 유지하며 같은 방을 다시 엽니다. 자동 복구는 5분 내 3회까지(1.5초·3초·6초 대기)이며 반복 실패하면 `주문 화면 열기`로 수동 재시도합니다. 복구 후 주문내역을 먼저 확인하세요. 앱이 제출 중이던 주문을 재전송하지 않으며, 충돌 당시 주문 성공 여부는 토스 주문내역에서 확인해야 합니다. 사용자가 Android 설정에서 앱을 강제 중지한 경우에는 자동으로 강제 중지를 해제하지 않습니다.

## 부팅 후 자동 실행

1. 앱을 실행해 관리자 PIN과 설치된 방을 먼저 저장합니다.
2. **관리자 설정 → PIN 인증 → 키오스크 설정 → 자동 실행 설정**을 누릅니다.
3. Android 선택창에서 **테이블 주문**을 선택하고 기본 홈 앱으로 지정합니다.
4. 홈 버튼으로 주문 화면에 돌아오는지 확인한 다음 재부팅합니다. 기기 화면 잠금이 있으면 잠금을 해제한 뒤 저장한 방이 열립니다.

기본 홈 앱은 Android가 부팅 후 실행하는 진입점입니다. 일반 앱의 백그라운드 실행에 의존하지 않습니다. 앱이 이미 실행 중이면 홈 복귀 때 현재 WebView를 재사용합니다. 프로세스가 종료되거나 재부팅되면 저장한 방 링크를 새로 엽니다. 토스 서버가 관리하는 장바구니·세션의 재부팅 후 유지는 보장하지 않습니다. [Android 공식 홈 앱 안내](https://developer.android.com/work/dpc/dedicated-devices/cookbook)

부팅 직후 인터넷 연결이 늦게 준비되면 연결 복구 후 최초 방 링크의 GET 요청만 최대 3회 재시도합니다. 화면이 정상으로 열린 뒤나 사용자가 조작한 뒤에는 자동 재시도를 중단합니다. 주문 전송·HTTP 오류·인증서 오류를 자동으로 재시도하지 않습니다.

**자동 실행 해제:** 같은 관리자 화면에서 `자동 실행 해제`를 누르면 자동 실행과 앱 잠금의 해제 상태를 앱에 저장하고, Android 화면에서 태블릿의 원래 홈 앱을 선택합니다. 기기 소유자로 등록한 앱이 지정한 홈 정책도 해제합니다. 선택을 취소해 주문 앱이 기본 홈으로 남아 있으면 자동 주문 화면 대신 `자동 실행 중지됨` 화면에서 수동으로 주문 화면을 열 수 있습니다. 다시 사용하려면 관리자에서 `자동 실행 설정`을 누릅니다.

## 화면 켜짐 유지

`주문 화면 켜짐 유지`를 켜고 저장하면 주문 앱이 화면에 보이는 동안 자동으로 꺼지지 않습니다. 끄면 태블릿의 화면 꺼짐 시간을 따릅니다. 기기의 전원 버튼과 잠금 화면 설정은 유지합니다.

## 주문 앱 잠금

이 앱을 **기기 소유자(Device Owner)**로 등록한 전용 태블릿에서 사용할 수 있습니다. 단순한 APK 설치나 일반 기기 관리자 활성화만으로는 사용할 수 없습니다. 일반 태블릿에서는 잠금 스위치를 비활성화하고 등록 필요 상태를 표시합니다.

등록 후 `관리자 설정 → 키오스크 설정 → 주문 앱 잠금`을 켜고 저장합니다. 홈·최근 앱·알림창을 통한 이탈이 제한되며, 전원 메뉴는 유지됩니다. 자동 실행도 함께 지정하면 재부팅 후 잠금이 다시 적용됩니다. 사용자가 직접 해제할 수 있는 Android 화면 고정과는 다릅니다. [Android 공식 Lock task 안내](https://developer.android.com/work/dpc/dedicated-devices/lock-task-mode)

### 개발·현장 시험용 등록

아래 명령은 **데이터가 없는 시험용 기기 또는 관리 등록을 위해 준비한 전용 기기**에서 관리자가 직접 수행하는 절차입니다. 기존 계정이나 다른 기기 관리자가 있으면 Android가 등록을 거절할 수 있습니다. 등록 실패 시 기존 기기를 임의로 초기화하지 말고 관리 상태를 먼저 확인합니다. 이 앱과 제공 스크립트는 공장 초기화를 실행하지 않습니다.

USB 디버깅 연결을 승인한 후 PowerShell에서 실행합니다. `$deviceSerial`에는 `adb devices`에 나온 대상 기기 번호를 입력합니다.

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb devices -l
$deviceSerial = Read-Host '설치할 전용 태블릿의 serial'
& $adb -s $deviceSerial install -r .\releases\unified\dogdive-order.apk
& $adb -s $deviceSerial shell dpm set-device-owner 'kr.dogdive.roomorder.tablet/kr.dogdive.roomorder.KioskAdminReceiver'
& $adb -s $deviceSerial shell am start -n 'kr.dogdive.roomorder.tablet/kr.dogdive.roomorder.RoomPickerActivity'
```

앱에서 `전용 기기 등록 완료`가 표시되는지 확인합니다. 기본 홈 앱 지정과 주문 앱 잠금은 관리자 설정에서 별도로 켭니다. QR/EMM을 이용한 대규모 관리 등록, 기존 EMM과의 정책 통합, 관리 등록 해제 자동화는 이번 APK에 포함하지 않습니다. [Android 공식 전용 기기 등록 안내](https://developer.android.com/work/dpc/dedicated-devices)

### 관리자 점검과 잠금 해제

- `관리자 설정 → PIN 인증 → 키오스크 설정`에서 `주문 앱 잠금`을 끄고 저장하면 잠금이 풀립니다.
- Wi-Fi 등의 점검은 `기기 설정 열기`를 누릅니다. 안내 확인 후 앱 잠금을 해제하고 Android 설정을 엽니다. **점검 후 앱 잠금을 다시 켜야 합니다.**
- Android 설정에서 돌아와 관리자 설정을 열면 PIN을 다시 요구합니다. 기기 설정을 여는 동작은 저장한 방이나 WebView 화면 설정을 바꾸지 않습니다.
- 외부 결제 앱 이동은 잠금 중 차단합니다. 필요한 경우 직원이 PIN으로 잠금을 해제한 뒤 진행합니다. 실제 POS 결제 흐름은 현장에서 별도 확인합니다.
- 공통 복구 PIN은 없습니다. 기기 소유자 등록은 유지되므로 앱 잠금 해제와 기기 관리 등록 해제는 별개입니다. PIN과 업데이트 서명 키는 매장 관리자가 보관합니다.

## 기기 상태 확인

```powershell
pwsh -File .\scripts\check-kiosk-device.ps1 -Serial $deviceSerial -ExpectHome -ExpectLock LOCKED
```

일반 자동 실행만 사용할 때는 `-ExpectLock NONE`으로 확인합니다. 스크립트는 기본 홈 앱·Android 버전·앱 버전·잠금 상태·전면 화면만 조회하며 설정을 변경하지 않습니다. 현장에서는 실제 재부팅, 홈·최근 앱 버튼, 알림창, PIN 점검 진입과 복귀를 확인합니다.

개발용 `scripts/test-kiosk-reboot.ps1`은 지정한 기기를 실제로 재부팅합니다. 이전 부팅의 종료 중 상태를 성공으로 판단하지 않도록 커널 부팅 ID 변경과 예상 전면 앱·잠금 상태를 함께 검사합니다.
