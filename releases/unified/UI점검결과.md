- 정리하는 동안 본문에 장바구니 비우기 → 빈 상태 확인 → 같은 방 재접속 단계를 표시합니다. 정리 실패 시 장바구니 확인 안내를 유지합니다.
- 관리자 시간 선택란은 20sp 글자와 최소 64dp 높이를 사용합니다. 큰 글자 설정에서 내용에 맞춰 높이가 늘어나도록 수정했습니다.

`captures/idle-v250`의 카운트다운·경고 화면은 에뮬레이터의 로컬 시험 화면입니다. 실제 주문·장바구니 변경 없이 검사했습니다. 검증 범위는 [검증 결과](VERIFICATION.md)를 참고하세요.

## 2.4.2 화면 변경

- 기본 밀도 160dpi에서 앱 전체는 1280×800, 왼쪽 탐색 영역은 168px, WebView는 1112×800입니다. 기존 2560×1600/320dpi 기기의 논리 크기만 확인하던 방식에서 실제 에뮬레이터 픽셀 크기를 변경했습니다.
- 웹 폭 960~1200px에서 메뉴 카드의 최소 높이를 144→128px, 카드 간격을 16→12px로 조정했습니다. 상품 상세는 사진보다 이름·가격·옵션 영역에 더 많은 폭을 배정합니다.
- 주문완료의 금액/결제 안내 카드와 주문내역 카드를 좌우로 배치했습니다. 웹 폭 960px 미만에서는 위아래로 전환합니다. 접기/펼치기와 내역 스크롤은 원본 페이지 동작을 유지합니다.
- 원본 접근성 금액을 애니메이션 없이 표시하고 `원`을 같은 줄에 유지합니다. 내역 버튼은 최소 72px이며 주문완료에 고정되어 있던 밝은 배경과 글자색을 다크모드에 맞췄습니다.
- 금액·메뉴·옵션을 앱에서 새로 계산하거나 생성하지 않습니다. 토스 DOM 구조가 확인되는 완료 화면만 보정하고, 관리자 설정에서 원래 배치로 돌아갈 수 있습니다.

## 검증 방법

실제 메뉴·상세·장바구니·확인창 표시와 로컬 주문완료 조회 fixture를 함께 사용했습니다. 주문완료는 미결제·부분결제·결제완료 3종, 123,456원, 두 자리 수량, 10개 긴 메뉴/옵션으로 검사합니다. `scripts/check-tablet-complete.mjs`는 모든 쓰기 요청을 차단하고 주문 조회 응답만 로컬 데이터로 대체하며, 실제 주문·결제를 실행하지 않습니다.

시험 도구의 화면 크기 강제 설정 중 일부 글리프가 찌그러지는 캡처 현상이 관찰됐습니다. 원래 크기로 복원한 Android 전체 화면 캡처에서는 정상 표시를 확인했습니다. 최종 배포 미리보기는 1280×800 전체 화면을 사용합니다.

실물 태블릿의 밀도·WebView 버전 차이, 실제 POS 접수·결제, 매장 장시간 운영은 별도 검증 대상입니다. 수치 결과와 배포 검증은 [검증 결과](VERIFICATION.md)를 참고하세요.

## 검증 범위

- 메뉴, 카테고리 선택, 무료/유료 상품 상세, 주문내역, 빈 장바구니, 긴 이름/두 자리 수량의 장바구니 시험 화면, 일반/긴 본문 확인창을 검사했습니다.
- WebView 글자 120%·140%, 가로 1112×800·856×600·720×480 CSS px, 밝은 모드·다크모드의 **108개 조합**에서 가로 넘침과 검사 대상의 48px 미만 터치 영역이 없었습니다.
- 140% 검사에는 가격 한 줄 유지, 확인창 화면 내 배치, 확인·취소 버튼 높이 64px 이상, 긴 본문 스크롤 검사를 추가했습니다.
- 실제 상세의 `+`/`−` 터치 후 수량과 합계가 원본 페이지 값에 맞춰 변경되고, 새 숫자 표시와 원본 값이 일치함을 확인했습니다. 담기 버튼을 누르지 않았습니다.
- 네이티브 화면은 1280×800dp·기본 글자와 1024×600dp·Android 글자 130%에서 두 테마를 검사했습니다. PIN 화면, 일반 설정, 키오스크 설정, 긴 확인창 **16개 조합**에서 글자 잘림 없이 저장 버튼까지 스크롤할 수 있었습니다.
- 관리자 인증 성공 상태는 별도 테스트 APK 안에서만 대체했습니다. PIN 조회·입력·변경은 하지 않았으며 배포 앱에 우회 경로를 추가하지 않았습니다. 별도로 실제 PIN 입력란을 터치해 키보드 표시 후에도 입력란과 버튼이 보이는 것을 확인했습니다.
- 장바구니 PATCH/DELETE 시험은 각각 요청을 지연한 동안 반복 터치 10회와 뒤로 가기 10회를 차단하고 현재 화면을 유지했습니다. 담기 시험은 6초 지연 중 반복 터치·뒤로 가기 각 12회에도 요청 1개만 발생했습니다. 모든 변경 요청은 로컬에서 응답했고 서버로 전송하지 않았습니다.
- Android Studio MCP 빌드·실행, 소스 검사, 릴리스 Lint를 통과했습니다. Lint 오류 0 / 기존 경고 16입니다.

실제 결제·POS 접수, 매장의 모든 옵션 조합, 실물 태블릿의 장시간 운영은 이번 점검에 포함하지 않았습니다. 장바구니의 긴 메뉴명과 확인창 긴 본문은 표시 전용 시험 데이터이며 앱에 고정 메뉴로 추가하지 않았습니다. 에뮬레이터 화면 검사로 실물 기기의 모든 렌더링 차이까지 검증한 것은 아닙니다.
