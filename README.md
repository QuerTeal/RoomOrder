# 테이블 주문 — 통합 Android 태블릿 앱

Android 13 가로 태블릿용 앱입니다. **같은 APK 하나**를 모든 태블릿에 설치하고, 관리자 설정에서 1·2·3·5·6·7·8·9번방 중 설치된 방을 선택합니다.

현재 배포 버전은 **2.7.0 (versionCode 19)**입니다. 기존 통합 앱 위에 설치하면 PIN·방·키오스크·다크모드·미조작 시간·애니메이션 설정을 유지합니다.

## 2.7.0 자동 업데이트

GitHub Releases에 올린 새 버전을 태블릿이 스스로 받아 설치합니다.

- **새벽 3~5시**에, 자동 정리 후 **쉬는 중**(빈 장바구니 확인, 이후 터치 없음)일 때만 확인·설치합니다. 손님이 쓰는 중이거나 영업 시간에는 설치하지 않습니다. 설치하는 동안 10~20초 주문 화면이 닫혔다가 다시 열립니다. 미조작 시 자동 정리를 `사용 안 함`으로 둔 태블릿은 자동으로 설치하지 않습니다.
- 받은 APK는 `update.json`의 SHA-256, 같은 패키지, 더 높은 버전, **같은 서명키**를 모두 확인한 뒤에만 설치합니다. 다른 저장소·HTTP 주소·다른 키로 서명된 파일은 설치하지 않습니다.
- 전용 기기(Device Owner)로 등록한 태블릿은 확인 없이 설치합니다. 등록하지 않은 태블릿은 Android가 설치 확인을 요구할 수 있는데, 이 확인창은 손님 화면에 띄우지 않고 **관리자 설정 → 앱 업데이트 → 지금 설치**에서 처리할 때까지 기다립니다. 한 번 앱이 직접 업데이트한 뒤에는 Android 12 이상에서 확인 없이 설치될 수 있습니다.
- 관리자 설정 → **앱 업데이트**에서 현재 버전, 마지막 확인 결과, `지금 확인`, `지금 설치`를 사용할 수 있습니다.

배포하는 방법:

1. 업데이트 파일은 배포 전용 공개 저장소 [QuerTeal/RoomOrder-releases](https://github.com/QuerTeal/RoomOrder-releases)에 올립니다(소스 코드는 비공개 저장소 QuerTeal/RoomOrder). `gradle.properties`의 `roomorder.updateRepo`에 설정되어 있으며, 이 값이 들어간 빌드부터 업데이트를 확인합니다. 2.7.0 배포 APK부터 이 저장소를 확인합니다.
2. `app/build.gradle`의 versionCode를 올리고 `pwsh -File .scriptsuild.ps1`로 서명 APK를 만듭니다.
3. GitHub CLI(`gh auth login`)를 준비한 뒤 `pwsh -File .scriptspublish-update.ps1`을 실행합니다. APK와 `update.json`(버전·SHA-256)을 최신 릴리스로 올립니다. `-DryRun`으로 `update.json`만 만들어 볼 수 있습니다.

공개 저장소에 올린 APK에는 방별 QR 주소가 들어 있습니다(테이블에 붙는 QR과 같은 주소). 서명키·`signing.properties`는 절대 올리지 마세요.

## 2.7.0 '지금은 이용할 수 없어요' 화면 자동 복구

토스 페이지는 데이터 요청이 한 번 실패하면(짧은 Wi-Fi 끊김, 토스 서버 오류 등) 전체 화면을 `지금은 이용할 수 없어요 / 문제를 해결하고 있어요` 안내로 바꿉니다. 토스는 이 화면에서 다시 시도하지 않고 버튼도 없어서, 누군가 `메뉴 처음으로`를 누를 때까지 그대로 멈춰 있었습니다.

- 이 화면이 4초 이상 유지되면 **같은 페이지를 다시 불러옵니다**. 계속 나오면 같은 방 QR로 다시 접속하며, 30초 → 2분 → 이후 5분마다 계속 시도합니다. 정상 화면이 10초 유지되면 처음부터 다시 셉니다. 왼쪽에는 `연결 문제로 화면을 다시 불러옵니다`를 표시합니다.
- 메뉴·상품 상세·장바구니·주문내역·주문완료 화면에서만 자동으로 다시 불러오고, 결제 단계는 손님이 직접 처리합니다. 요청 처리 중이거나 주문 결과가 불확실하면 기다립니다.
- 연결이 끊겨 앱의 `주문 화면을 열지 못했어요` 안내가 나온 경우도 같은 페이지를 자동으로 다시 엽니다. Android가 네트워크 연결을 다시 확인하면 바로, 그렇지 않으면 위와 같은 간격으로 시도합니다. 이전에는 앱 시작 때만 자동으로 다시 시도했습니다.
- 모두 GET으로 페이지만 다시 열며, 장바구니 변경·주문 요청을 다시 보내지 않습니다.

## 2.6.1 장시간 대기 후 QR 만료 방지

2.5.2부터 자동 정리가 끝나면 다음 터치까지 쉬는데, 쉬는 시간이 길어지면 토스의 테이블 접속이 끝나 첫 메뉴 터치에서 `QR을 다시 인식해주세요` 화면이 나왔습니다. 이제 쉬는 동안에도 접속을 유지합니다.

- 쉬는 동안 **10분마다 같은 방의 원본 QR 주소로 조용히 다시 접속**합니다. 정리로 빈 장바구니를 확인했고 그 뒤 아무도 터치하지 않은 메뉴 화면에서만 실행하며, 카운트다운은 계속 숨깁니다. 100초마다 재접속하던 2.5.1(하루 약 800회)보다 적은 하루 최대 144회입니다.
- 화면이 꺼져 있었거나 네트워크·팝업 때문에 재접속하지 못한 채 10분이 지났다면, 주문 화면의 **첫 터치로 먼저 QR에 다시 접속**합니다. 그 터치는 메뉴에 전달하지 않고 1~3초 로딩 뒤 새 메뉴가 열리며, 평소처럼 자동 정리 카운트다운이 시작됩니다. 왼쪽 버튼(뒤로·처음으로·관리자)은 그대로 동작합니다.
- 주문/결제 화면, 처리 중인 요청, 결과 불확실 상태, 확인창, 정리 실패 상태에서는 재접속하지 않습니다. 미조작 시 자동 정리를 **사용 안 함**으로 두면 장바구니를 확인할 수 없으므로 이 기능도 동작하지 않습니다.
- 토스 서버의 실제 접속 유지 시간은 공개되어 있지 않습니다. 10분 간격은 이보다 충분히 짧다고 가정한 값이며, 만료 화면이 나오면 기존처럼 4~6초 뒤 자동으로 같은 방 메뉴로 돌아갑니다.

## 2.6.0 애니메이션 설정

**관리자 설정 → PIN 인증 → 화면 설정 → 애니메이션**에서 토스 원본 효과를 효과별로 조정하고 저장합니다. 기본값은 모두 켬·원본 크기(2.5.3과 동일)이며, 저장하면 현재 주문 화면에 바로 적용됩니다. 가로화면 최적화를 끈 원래 배치에서도 같이 적용됩니다.

| 항목 | 선택 | 끄면 |
|---|---|---|
| 금액·수량 숫자 굴림 | 켬/끔 | 하단 버튼과 주문완료 금액을 현재 값으로 바로 표시 |
| 주문완료 화면 효과 | 켬/끔 | 파란 원·체크·쿠폰 안내 시작 화면을 건너뛰고 결과 카드를 바로 표시. 페이지의 쿠폰 배너는 유지 |
| 담기 버튼 움직임 | 끔 / 작게 5px / 중간 10px / 원본 20px | 버튼이 움직이지 않음. 크기를 줄이면 원본의 속도·주기는 그대로 두고 오르내리는 높이만 줄임 |

## 2.5.3 원본 애니메이션 복구

- 2.3.0~2.4.2에서 가로 보정이 끄던 토스 원본 애니메이션을 다시 표시합니다.
  - 하단 담기 버튼의 수량·금액 숫자가 굴러가며 바뀌는 효과
  - 담기 버튼이 2초 주기로 위아래로 움직이는 효과
  - 주문완료 화면의 체크 표시, 금액이 0원부터 올라가는 효과, 카드 등장 효과
- 당시 숫자 칸 주변에 보이던 흰색·검은색 띠는 화면 캡처 도구에서만 생기는 현상이었습니다. 실제 기기 화면에서는 원본 애니메이션이 정상적으로 표시됩니다.
- 가로 배치, 큰 글자, 버튼 최소 크기 보정은 그대로입니다. 큰 글자에서 수량 배지 숫자가 잘리지 않게 하는 하단 글자 보정도 유지합니다. 주문완료 금액은 원본이 계산한 폭을 그대로 사용해 카드 안에서 `원`과 같은 줄에 표시합니다.

## 2.5.2 자동 정리 반복 방지·외부 페이지 복귀·안내 간소화

- 자동 정리가 끝나면 **다음 터치까지 쉽니다**. 아무도 없는 태블릿이 설정 시간마다 QR에 계속 재접속하던 반복(100초 기준 하루 약 800회)을 없앴습니다. 쉬는 동안 카운트다운을 숨기고, 화면을 터치하면 새 주기를 시작합니다. QR 만료 화면 자동 복귀는 그대로 동작합니다.
- 토스 주문 페이지가 아닌 외부 https 페이지에 머물러도 미조작 시간이 지나면 장바구니를 정리하고 같은 방 메뉴로 돌아옵니다. 메뉴·장바구니·주문내역에서 나간 경우에만 적용합니다. 결제 단계에서 다른 사이트로 이어진 경우는 결제 중일 수 있으므로 자동으로 이동하지 않습니다.
- 장바구니 삭제와 빈 상태 확인은 새로 불러온 페이지가 표시된 뒤에만 실행합니다. 응답이 느릴 때 이전 화면을 기준으로 삭제하거나 비었다고 판단하던 경우를 막았습니다.
- 왼쪽 안내 문구를 줄이고 `계속 사용` 버튼을 없앴습니다. 화면 어디든 터치하면 정리가 취소됩니다.

## 2.5.1 초 단위 자동 새로고침·장바구니 정리

- 기본값은 **100초 미조작**입니다. 관리자 설정 → PIN 인증 → **미조작 시 자동 정리**에서 사용 안 함/60초/80초/100초를 선택하고 저장합니다. 기존 분 단위 설정은 100초로 전환하며, 사용 안 함은 유지합니다.
- 왼쪽에 남은 시간을 `분:초`로 계속 표시하고, 마지막 60초에는 장바구니 비우기와 새로고침 안내·`계속 사용` 버튼을 표시합니다. 화면을 터치하면 카운트다운을 처음부터 다시 시작합니다.
- 60초를 선택하면 처음부터 정리 안내가 표시됩니다. 80초는 20초 경과 후, 100초는 40초 경과 후 안내로 전환합니다.
- 시간이 끝나면 원본 장바구니를 새로 조회하고 삭제 버튼을 한 항목씩 실행합니다. 빈 상태를 다시 조회해 확인한 뒤 **저장된 같은 방의 원본 QR 주소로 재접속**합니다. 정상 메뉴를 확인하면 다음 주기를 시작합니다.
- QR의 중간 주소를 거치는 동안 정리가 중단되던 현상도 수정했습니다. 저장된 해당 방 QR 주소에서 메뉴 연결을 기다리며, 전체 처리 제한 시간은 유지합니다.
- 주문/결제 화면·처리 중인 요청·결과 불확실 상태·확인창에서는 정리를 보류합니다. 다시 정리할 수 있을 때 60초 안내 시간을 확보합니다. 앱이 백그라운드로 가거나 관리자 화면으로 이동하면 실행을 중단하고, 돌아오면 새 주기를 시작합니다. 정리 중 뒤로 가기와 메뉴 이동은 잠시 막습니다.
- 삭제 실패·20초 무응답·알 수 없는 장바구니 구조에서는 자동 정리를 중단하고 확인 안내를 표시합니다. 삭제 요청을 재전송하지 않으며, 전체 정리도 2분을 넘기면 중단합니다.
- 정리 대상은 아직 주문하지 않은 장바구니입니다. 접수된 주문과 주문내역, PIN·방·키오스크 설정을 유지합니다. 여러 사람이 함께 보는 장바구니라면 해당 태블릿의 미조작 시간을 기준으로 정리된다는 점을 운영 시 고려하세요.

주기적인 원본 QR 재접속으로 오래된 화면과 세션을 갱신하는 기능입니다. 토스 서버의 만료 정책을 변경하거나 만료 방지를 보장하는 기능은 아닙니다. 기존 QR 만료 감지·자동 복귀도 함께 유지합니다.

## 2.4.2 1280×800 및 주문완료 화면

- 1280×800 가로 화면에서 메뉴 카드 간격과 상세 사진/정보 비율을 조정했습니다. 기본 밀도 160dpi에서는 왼쪽 탐색 영역을 제외한 웹 영역이 1112×800 CSS px입니다. 기기의 표시 밀도에 따라 웹 영역은 달라집니다.
- 주문완료 화면은 완료 금액·결제 안내와 주문내역을 좌우로 배치합니다. 웹 폭이 960px 미만이면 위아래로 배치하여 큰 글자와 긴 내역을 스크롤할 수 있습니다.
- 주문완료 금액은 원본 현재 값을 애니메이션 없이 표시하며 `원`을 같은 줄에 유지합니다. 주문내역의 펼치기/접기, 메뉴 복귀, 결제 안내는 토스 원본 동작을 사용합니다.
- 주문완료 카드·배경·안내 문구에 밝음/어두움 테마를 적용했습니다. 검증 범위와 실물 기기에서 남은 확인은 [검증 결과](VERIFICATION.md)를 참고하세요.

## 2.4.1 UI 점검 및 보정

- 좁은 상세 화면에서도 가격과 `원`을 한 줄로 표시하고, 필요하면 수량 조절기를 다음 줄에 배치합니다.
- 하단 수량·금액은 원본 페이지의 현재 값을 유지하면서 불안정한 숫자 애니메이션을 제거했습니다.
- 앱 자체 확인창의 제목·본문·버튼을 키우고 버튼 높이를 최소 64dp로 맞췄습니다.
- 밝음/어두움, 글자 120%/140%, 세 가지 가로 크기에서 108개 웹 화면 조합을 점검했습니다. [UI 점검 결과](UI-REVIEW.md)에 세부 범위와 한계를 기록했습니다.

## 2.4.0 다크모드

- **관리자 설정 → PIN 인증 → 다크모드 → 저장**에서 켜고 끕니다. 기본값은 꺼짐이며 각 태블릿에 저장되고 앱을 다시 실행해도 유지됩니다.
- 메뉴·상품 상세·장바구니·주문 확인창과 앱의 탐색 버튼·로딩·오류·복구·관리자 화면에 적용됩니다.
- 테마만 변경하면 현재 WebView를 유지한 채 색상을 바꿉니다. `현재 페이지 새로고침`을 별도로 선택한 경우에만 새로고침합니다.
- 메뉴 사진을 반전시키지 않습니다. 토스의 색상 토큰을 사용하고 고정 색상이 남은 수량·취소 버튼·카테고리 배경을 보정합니다.
- Android 13 에뮬레이터에서 관리자 저장·유지, 7개 화면/크기 조합, 54개 표시 글자·버튼 대비, 수량/삭제 입력 보호를 확인했습니다. 실제 태블릿과 실제 주문·결제는 별도 검수 대상입니다.

## 2.3.4 장시간 미조작 후 QR 만료 자동 복귀

- 토스의 `QR을 다시 인식해주세요` 만료 화면도 자동 복귀 대상으로 인식합니다. 화면이 4초 이상 유지되면 저장된 방의 원본 QR 링크를 GET으로 다시 엽니다. 검사 간격을 포함한 복귀 시작은 보통 약 4~6초이며 메뉴 로딩 시간은 별도입니다.
- 정상 메뉴·장바구니·결제 입력·확인창은 유지합니다. 변경 요청이 아직 진행 중이면 기다리며, 주문·결제 결과가 불확실하면 자동으로 이동하지 않고 결과 확인 안내를 유지합니다.
- 실패한 장바구니 요청의 대기 안내 뒤에 QR 만료 화면이 나타난 경우도 인식합니다. 정상 메뉴 복귀 후 만료된 뒤로 가기 기록을 지웁니다.
- 기존 최대 3회 복귀 제한·재시도 간격과 정상 메뉴 확인 후 제한 초기화를 유지합니다. 쿠키·장바구니 데이터를 앱에서 삭제하거나 주문 요청을 자동 재전송하지 않습니다.
- 토스 서버의 만료 시간을 연장하는 기능은 아니며, 만료 화면에서 같은 방 메뉴로 자동 재접속하는 방식입니다.

## 2.3.3 필요한 경우에만 대기 화면 표시

- 상세 수량·옵션 선택과 장바구니 수량 변경·삭제는 현재 화면을 유지합니다. 모든 버튼에 표시하던 전체 화면 준비 안내를 없앴습니다.
- 장바구니 변경 요청 중에는 응답이 끝날 때까지 중복 입력과 뒤로 가기를 차단합니다. 입력 잠금과 전체 화면 표시를 분리했습니다.
- 초기 로딩, 실제 페이지 이동, 담기·주문·결제 처리에는 대기 안내를 유지합니다. 수량 변경·삭제도 결과가 불확실해지면 장바구니 확인 안내를 표시합니다.
- 새 고객 안내 문구나 고정 메뉴 데이터를 추가하지 않았습니다.

## 2.3.2 화면 전환과 반복 입력 방지

- 페이지 시작 시점부터 가로 보정을 적용하며, 화면 전환 중 원래 세로 폭 화면이 먼저 보이지 않도록 준비 안내를 표시합니다. 새 화면이 그려진 뒤 입력을 다시 허용합니다.
- 장바구니 담기·수량 변경·주문·결제 요청 처리 중에는 반복 터치와 뒤로 가기를 차단합니다. 응답 헤더뿐 아니라 본문 수신과 화면 전환이 끝날 때까지 기다립니다.
- 시간이 오래 걸리면 대기 안내를 표시합니다. 시간 초과·연결 끊김·실패 응답으로 결과를 확인할 수 없으면 바로 재전송하지 않고 `장바구니 확인` 또는 `주문내역 확인`으로 안내합니다.
- 기존 주문 요청·본문·토큰을 변경하거나 자동으로 재전송하지 않습니다. 실제 POS의 주문 접수 여부는 주문내역에서 확인해야 합니다.

Android 13 에뮬레이터에서 지연된 실제 장바구니 버튼 입력, 시간 초과, CPU 6배 지연·네트워크 300ms 지연의 화면 전환을 검증했습니다. 검사 요청은 서버에 전송하지 않고 로컬에서 응답했으며, 실물 태블릿·실제 POS 주문 검증은 별도입니다.

## 2.3.1 종료 복구

- 개발 에뮬레이터의 Android System WebView 149.0.7827.163에서 확인된 `NetworkService` 네이티브 충돌에 대응했습니다. 주문 화면 프로세스가 종료돼도 별도 네이티브 화면을 유지하고 저장된 방의 첫 메뉴를 다시 엽니다.
- 렌더러만 종료되는 경우에도 손상된 WebView를 제거한 뒤 복구합니다. Android가 충돌 화면의 호출 화면까지 종료하는 경로는 별도 내부 Activity로 격리합니다.
- 복구는 1.5초·3초·6초 간격, 5분 내 자동 3회까지입니다. 오류가 반복되면 앱 안에 직원 안내와 `주문 화면 열기` 버튼을 남깁니다. 관리자 설정은 PIN 인증을 유지합니다.
- 원본 방 QR 링크를 GET으로 열며 주문 요청을 재전송하지 않습니다. 복구 후에는 재주문 전에 주문내역을 확인하도록 안내합니다. 충돌 당시 제출 중이던 주문의 성공 여부나 장바구니 유지는 앱에서 보장할 수 없습니다.
- 앱의 복구 경로를 보완한 것으로, 기기에 설치된 WebView 엔진 자체의 오류를 수정한 것은 아닙니다. 실제 운영 태블릿의 연속 사용 확인은 필요합니다.

## 2.3.0 수정 사항

- “이대로 주문할까요?” 확인창의 줄 높이 오류를 수정했습니다. 제목·설명 사이 여백, 팝업 폭, 긴 본문 스크롤, 최소 64px 확인 버튼을 적용했습니다.
- 세션 종료 안내(“안녕히 가세요” 또는 토스의 현재 종료 문구)가 4초 이상 유지되면 저장된 방의 원본 QR 링크를 GET으로 다시 엽니다. 정상 메뉴가 열리면 이전 종료 화면의 뒤로 가기 기록을 지웁니다.
- 단순 주문 완료·주문내역·장바구니·결제 입력·확인 팝업에서는 자동 복귀하지 않습니다. 관리자 설정이나 다른 창으로 이동하면 복귀 대기를 중단합니다. 표시 방 번호와 PIN 설정은 바꾸지 않습니다.
- 자동 복귀는 연속 실패 시 최대 3회, 재시도 사이 30초/120초 대기입니다. 정상 메뉴를 10초 확인하면 제한을 초기화합니다. 반복 실패 시 “메뉴 처음으로” 버튼으로 다시 접속할 수 있습니다.
- 장바구니 옵션·수량 버튼 줄바꿈, 하단 수량 배지 높이와 버튼 움직임을 보완했습니다.

검증 범위와 한계는 [검증 결과](VERIFICATION.md)를 참고하세요.

## 설치 및 사용

1. `releases/unified/dogdive-order.apk`를 태블릿에 복사해 설치합니다.
2. `테이블 주문`을 실행하고 관리자가 사용할 숫자 6자리 PIN을 두 번 입력합니다. 기본 PIN은 없습니다.
3. 실제 설치된 방을 선택하고 저장합니다. 다음 실행부터 해당 방 주문 화면이 열립니다.
4. 앱의 방 번호와 토스 페이지의 테이블 번호가 같은지 확인합니다.
5. `관리자 설정` → PIN 인증 후 방·가로 배치·글자 크기·다크모드·애니메이션을 변경할 수 있습니다.

`releases/room-N.apk`와 `RoomOrder-Android13-v1.0.0.zip`은 이전 방별 버전입니다. 새 통합 버전은 `releases/unified`를 사용합니다. 이전 방별 앱의 설정은 자동 이전되지 않습니다. 기존 다른 서명의 통합 앱(`kr.dogdive.roomorder`)과도 충돌하지 않도록 새 패키지 ID를 사용합니다.

## 화면과 관리자 보호

- 고객 화면: 방 번호, 뒤로, 메뉴 처음으로, 관리자 진입 버튼. 버튼은 최소 64dp, 기본 글자 20sp입니다.
- 방 변경, 원본 배치 전환, 글자 크기, 다크모드, 애니메이션, 페이지 새로고침, PIN 변경은 인증한 관리자만 사용할 수 있습니다.
- PIN은 소금값(salt)을 포함한 PBKDF2 해시로 저장합니다. 5회 실패하면 30초 잠금이 적용됩니다. 설정 화면을 벗어나거나 앱이 재생성되면 다시 인증합니다. 관리자 화면에서 2분 동안 조작이 없어도 자동 잠금됩니다.
- 관리자 화면은 화면 캡처·최근 앱 미리보기를 보호하며 PIN 입력값을 복원하거나 자동 완성하지 않습니다.
- WebView 기본 글자 크기는 120%이고, 관리자는 100·120·140% 중 선택할 수 있습니다.
- 가로 WebView 폭 720 CSS px 이상에서 메뉴·장바구니는 2열, 사진이 있는 상품 상세는 사진·정보를 좌우로 배치합니다. 작은 화면과 확인되지 않은 경로는 원래 배치를 유지합니다.
- 수량·탭 등 웹 터치 영역은 최소 56px, 하단 담기·주문 버튼은 최소 72px입니다. 토스의 기존 버튼과 상품 옵션 동작을 유지합니다.

## 실제 데이터 및 세션

매장명·메뉴·가격·품절·옵션·장바구니·주문내역은 토스 페이지에서 실시간으로 표시합니다. 가짜 메뉴나 고정 매장 문구는 넣지 않습니다. 앱 자체 안내 문구는 Android `strings.xml`, 배포용 방 링크는 `rooms.xml`에서 관리합니다. 문구는 코드나 가로 보정 스크립트에 직접 넣지 않습니다.

하나의 앱 안에서 각 방은 별도 프로세스와 별도 WebView 저장 경로를 사용합니다. 방 전환 시 쿠키와 저장소를 섞지 않습니다. 방 변경이나 메뉴 처음으로 이동은 서버의 주문·장바구니를 취소하지 않습니다. 손님 교체와 주문 마감은 토스 매장 운영 절차에 따릅니다.

인터넷 연결이 필요합니다. 인증서 오류와 HTTP 혼합 콘텐츠는 차단하고, 주문을 자동 재전송하지 않습니다.

종료 감지는 현재 토스 페이지의 번역 데이터·종료 안내·세션 만료 표시를 함께 확인합니다. 메뉴/가격을 읽어 다시 만들거나 주문 API를 호출하지 않습니다. 원본 QR 진입 과정에서 토스가 만료 상태를 갱신하며, 앱이 쿠키나 장바구니 저장소를 일괄 삭제하지 않습니다.

## 키오스크 기능 (2.2.0)

관리자 설정에서 기본 홈 앱을 지정하면 부팅 후 저장한 방이 열리고 홈 버튼으로 현재 주문 화면에 복귀합니다. 화면 켜짐 유지도 켜거나 끌 수 있습니다. 기기 소유자로 등록한 전용 태블릿에서는 홈·최근 앱·알림창을 제한하는 주문 앱 잠금을 지원합니다. PIN 인증 후 잠금 해제와 Android 기기 설정 진입이 가능합니다.

자동 실행은 기본 홈 앱 지정이 필요하고, 기기 잠금이 있으면 먼저 해제해야 합니다. 전용 기기 등록 없는 일반 설치에서는 앱 잠금을 사용할 수 없습니다. 설정·해제·ADB 등록·점검 방법은 [키오스크 설치 안내](KIOSK.md)를 따릅니다.

PIN 분실 시 사용할 공통 복구 PIN은 없습니다. 앱 데이터 초기화는 로컬 설정과 방별 세션을 삭제하므로 매장 관리자 확인 후 진행해야 합니다.

## 개발 및 빌드

JDK 17, Android SDK Platform 36, Build Tools 36.0.0, PowerShell 7, Gradle 9.6.0 Wrapper를 사용합니다. minSdk/targetSdk는 33입니다.

```powershell
pwsh -File .\scripts\check-source.ps1
pwsh -File .\scripts\build.ps1
pwsh -File .\scripts\verify-apks.ps1
```

릴리스 패키지는 `kr.dogdive.roomorder.tablet`, 개발용은 `kr.dogdive.roomorder.dev`입니다. 개발용 앱은 별도로 설치되며 배포 APK에는 WebView 디버깅을 노출하지 않습니다.

`tablet-release.jks`와 `signing.properties`는 업데이트 서명용 비공개 자료입니다. 두 파일은 Git과 배포 묶음에서 제외하고 별도로 백업합니다. 같은 키와 증가한 versionCode로 업데이트합니다.

두 파일이 없으면 `build.ps1`은 빌드를 멈추고 백업 복원을 안내합니다. 새 키로 서명한 APK는 설치된 태블릿을 업데이트할 수 없기 때문입니다. 처음 배포할 때만 `-CreateReleaseKey`를 붙여 새 키를 만듭니다.

주요 파일:

- `app/src/main/java/kr/dogdive/roomorder/AdminActivity.java`: PIN 인증과 관리자 설정
- `SettingsStore.java`: 기본 프로세스의 설정 저장 및 방 프로세스로 전달
- `Rooms.java`: 방별 독립 WebView 프로세스
- `MainActivity.java`: 고객 화면 및 웹 연결
- `IdleRefresh.java`: 미조작 시간·카운트다운·보류 시간 계산
- `Motion.java`: 담기 버튼 움직임 크기 선택지와 기본값
- `app/src/main/assets/cart-maintenance.js`: 원본 장바구니 삭제 버튼을 통한 순차 정리와 빈 상태 확인
- `app/src/main/assets/tablet.js`: 콘텐츠·이벤트를 복제하지 않는 가로 배치 보정
- `app/src/main/assets/theme.js`: 사진·원본 컨트롤을 유지하는 웹 색상 전환
- `app/src/main/res/values/strings.xml`: 앱 안내 문구
- `app/src/main/res/values/rooms.xml`: 제공받은 8개 원본 링크

## Android Studio MCP

Android Studio MCP 서버 주소: `http://127.0.0.1:64342/stream`.
이 작업 환경에는 `android_studio` 서버로 등록되어 있습니다. `scripts/android-studio-mcp.ps1`은 MCP 초기화·도구 호출·세션 정리를 지원합니다.

```powershell
$argsJson = @{projectPath=$PWD.Path.Replace('\','/');timeout=120000} | ConvertTo-Json -Compress
& .\scripts\android-studio-mcp.ps1 -Tool build_project -ArgumentsJson $argsJson
```

이 IDE 버전의 일반 MCP `execute_run_configuration`은 Android 장치 대신 `<default>` 대상을 선택하여 실패합니다.
